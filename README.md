# Xmix — سوق التجارة العام 🛍️

منصة تجارة إلكترونية عُمانية عامة تجمع **ثلاث ركائز أساسية** في سوق واحد:

1. **منتجات** 📦 — تشكيلة واسعة من المنتجات داخل محلات موثوقة
2. **خدمات** 🛠️ — خدمات احترافية تُطلب أو تُحجز مباشرة من المحلات
3. **توصيل** 🚚 — شبكة توصيل تغطي محافظات سلطنة عُمان كلها

بنية السوق قائمة على **المحلات (الدكاكين)**: كل محل يملك واجهة خاصة بعلامته، وبداخله منتجاته وخدماته — بينما يتسوّق الزبون من كل المحلات بسلة واحدة وطلب واحد وتجربة موحّدة.

الموقع يبدأ **نظيفاً بلا أي بيانات تجريبية** — المنتجات والخدمات والأسعار والصور تُدار بالكامل من لوحات التحكم بعد النشر.

الموقع مبني بـ **Next.js 16** وجاهز تماماً للنشر على **Vercel** مع قاعدة بيانات **PostgreSQL** على **Supabase**.

## 🚀 خطوات النشر الكاملة (GitHub + Supabase + Vercel)

### الخطوة 1️⃣ — إنشاء قاعدة البيانات على Supabase (مجاني)

1. افتح [supabase.com](https://supabase.com) وأنشئ حساباً مجانياً.
2. اضغط **New project** واختر اسماً مثل `xmix`، وحدد كلمة مرور لقاعدة البيانات (**احفظها!**)، وأقرب منطقة (مثل `Frankfurt` أو `London`).
3. بعد إنشاء المشروع، من القائمة الجانبية افتح **SQL Editor**.
4. افتح الملف [`database/setup-database.sql`](database/setup-database.sql) وانسخ **كامل محتواه** والصقه في المحرر ثم اضغط **Run**.
5. ستظهر رسالة نجاح — الآن قاعدتك تحتوي على **بداية نظيفة**: محل Xmix الرئيسي (بدون منتجات) + حساب مسؤول النظام + حساب التاجر. ✅
6. انسخ رابط الاتصال:
   - من **Project Settings (⚙️) → Database → Connection string → URI**
   - اختر تبويب **Transaction pooler** (المناسب لـ Vercel)
   - استبدل `[YOUR-PASSWORD]` بكلمة مرور قاعدة البيانات التي حفظتها
   - أضف في نهاية الرابط: `?pgbouncer=true`
   - س يكون بالشكل:
     ```
     postgresql://postgres.xxxx:كلمة_المرور@aws-0-region.pooler.supabase.com:6543/postgres?pgbouncer=true
     ```

> 💡 هذا الملف آمن لإعادة التشغيل: يحذف الجداول القديمة وينشئها من جديد.
> 💡 إذا واجهت مشكلة في الاتصال لاحقاً، استخدم رابط **Session pooler** (المنفذ 5432) بدلاً منه.

### الخطوة 2️⃣ — رفع المشروع إلى GitHub

**الطريقة السهلة (من المتصفح — بدون أي برامج):**

1. أنشئ مستودعاً جديداً على [github.com/new](https://github.com/new) باسم `xmix` (اختر **Private** للحفاظ على خصوصية المتجر).
2. لا تضف أي ملفات ابتدائية (اترك README و .gitignore فارغة).
3. من صفحة المستودع اضغط الرابط **uploading an existing file**.
4. اسحب وأفلت **محتويات** مجلد المشروع (كل الملفات والمجلدات، وليس المجلد نفسه).
   - ⚠️ تأكد أنك لا ترفع: `node_modules`، `.next`، `.env` — هذه غير موجودة أصلاً في الملف المضغوط الجاهز.
5. اضغط Commit changes وانتظر انتهاء الرفع.

**الطريقة الاحترافية (سطر الأوامر):**

```bash
# بعد فك ضغط المشروع والدخول إلى مجلده
git init
git add .
git commit -m "Xmix store — initial release"
git branch -M main
git remote add origin https://github.com/USERNAME/xmix.git
git push -u origin main
```

### الخطوة 3️⃣ — النشر على Vercel

1. افتح [vercel.com](https://vercel.com) وسجّل الدخول بحساب GitHub.
2. اضغط **Add New → Project** واختر مستودع `xmix`.
3. Vercel سيكتشف Next.js تلقائياً — لا تغيّر إعدادات البناء.
4. افتح قسم **Environment Variables** وأضف المتغيرين التاليين:

| الاسم | القيمة |
|---|---|
| `DATABASE_URL` | رابط الاتصال من Supabase (الخطوة 1) |
| `AUTH_SECRET` | **ولّد قيمة خاصة بك** — نفّذ `openssl rand -hex 32` في طرفيتك والصق الناتج. لا تستخدم قيمة منشورة علناً أبداً |

> 🔐 **لماذا؟** مفتاح الجلسات يوقّع كوكيز الدخول؛ أي شخص يعرف المفتاح يستطيع انتحال جلسة مسؤول النظام. لذلك يجب أن يكون سرياً وفريداً لكل نشر.

5. اضغط **Deploy** وانتظر دقيقتين. 🎉
6. ستحصل على رابط مثل `https://xmix.vercel.app` — موقعك يعمل الآن بالكامل!

### الخطوة 4️⃣ — التحقق بعد النشر

- [ ] الصفحة الرئيسية تعرض الركائز الثلاث (منتجات/خدمات/توصيل) والمحل الرئيسي (بدون منتجات بعد — طبيعي!)
- [ ] سجّل دخول بحساب **مسؤول النظام** وافتح «لوحة إدارة النظام» من قائمة الحساب
- [ ] سجّل دخول بحساب التاجر وأضف أول منتج حقيقي — وجرّب إضافة **خدمة** بنوع «خدمة»
- [ ] سجّل حساباً زبوناً ثم امنحه صلاحية تاجر من لوحة المسؤول (اختياري)
- [ ] أضف منتجاً للسلة وأكمل طلباً — سيظهر فوراً في لوحة المسؤول ولوحة التاجر
- [ ] جرّب تبديل اللغة عربي ⇄ إنجليزي
- [ ] **غيّر كلمتي مرور الحسابين الافتراضيين فوراً** — كونها منشورة في هذا الملف يجعل تغييرها إلزامياً وليس اختيارياً

## 🔑 حسابات النظام (بعد تنفيذ ملف قاعدة البيانات)

| الحساب | البريد الإلكتروني | كلمة المرور | الدور |
|---|---|---|---|
| **مسؤول النظام** | `admin@xmix.om` | `Xmix@Admin2026` ⚠️ غيّرها فوراً | يرى كل الحسابات والمحلات والطلبات — يمنح صلاحيات التجار ويدير المنصة كاملة |
| **تاجر المحل الرئيسي** | `owner@xmix.om` | `Xmix@2026` ⚠️ غيّرها فوراً | يدير منتجات وخدمات المحل الرئيسي وأسعارها ومخزونها وصورها من لوحة صاحب المحل |

> 🔒 **إلزامي:** كلمات المرور أعلاه منشورة في هذا المستودع، لذلك **تغييرها بعد أول دخول شرط أمني لا خيار** — استخدم كلمات قوية فريدة (أو عدّلها في `scripts/seed.ts` ثم أعد التنفيذ)، وتأكد أن مستودع GitHub خاص (Private)، ولا تشارك بيانات المسؤول مع أحد.

## 🛡️ كيف تعمل منظومة المحلات والصلاحيات؟

**فتح محل جديد لعميل مسجّل:**
1. يفتح المسؤول «لوحة إدارة النظام ← الحسابات».
2. يضغط «منح صلاحية تاجر» بجانب الحساب ويدخل اسم المحل (والقسم والمدينة اختيارياً).
3. يُنشأ المحل فوراً ويصبح ظاهراً في السوق، ويصبح الحساب تاجراً يملك لوحة تحكم خاصة به.

**اعتماد طلب انضمام من نموذج «افتح محلك»:**
1. الزائر يعبّي نموذج الانضمام في الموقع.
2. يصل الطلب إلى تبويب «طلبات الانضمام» في لوحة المسؤول (مع شارة عدّاد حمراء).
3. الضغط على «اعتماد وإنشاء الحساب» ينشئ المحل + حساب التاجر تلقائياً:
   - إن كان بريد مقدّم الطلب مسجلاً مسبقاً ← تُمنح الصلاحية لنفس الحساب.
   - إن لم يكن مسجلاً ← يُنشأ حساب جديد ويظهر المسؤول بكلمة مرور مؤقتة ينسخها ويرسلها للتاجر.

**إدارة المحلات:** اعتماد محل بانتظار الموافقة، تعليق محل مخالف (يختفي من السوق مع بقاء عروضه)، أو إعادة تنشيطه.

**الطلبات:** المسؤول يرى كل طلبات السوق (مع بيانات العميل والعناصر)، ويحدّث حالتها: قيد المعالجة ← قيد التجهيز ← تم التوصيل / ملغي.

> ملاحظة: حساب مسؤول النظام لا يمكن منحه صلاحية تاجر ولا إلغاء صلاحيته — حماية مدمجة.

## 💻 التشغيل المحلي (اختياري)

```bash
# 1) ثبّت الحزم
npm install

# 2) انسخ ملف البيئة وعدّل رابط قاعدة البيانات
cp .env.example .env
#   ضع في DATABASE_URL رابط Supabase الخاص بك

# 3) جهّز قاعدة البيانات (إن لم تكن جاهزة)

npm run db:seed

```

## 📜 أوامر قاعدة البيانات

| الأمر | الوظيفة |
|---|---|
| `npm run db:push` | إنشاء/تحديث الجداول |
| `npm run db:seed` | زرع بداية نظيفة (المحل الرئيسي + المسؤول + التاجر — يحذف أي بيانات أخرى) |
| `npm run db:deploy` | push + seed معاً (إعداد سريع) |

## 🛡️ ملاحظات أمنية

- كلمات المرور مخزّنة بتهاش scrypt ولا يمكن استرجاعها.
- جلسات الدخول موقّعة HMAC-SHA256 عبر `AUTH_SECRET` — **لا تشارك هذا المفتاح ولا تنشره أبداً**؛ ولّد قيمة فريدة لكل نشر بـ `openssl rand -hex 32`. عند غيابه في الإنتاج يولّد النظام سراً مؤقتاً عشوائياً (تنتهي الجلسات مع كل نشر) بدل استخدام قيمة ثابتة معروفة.
- أسعار الطلبات يُعاد حسابها في الخادم من قاعدة البيانات عند إنشاء الطلب — الأسعار والأسماء المرسلة من المتصفح تُتجاهل تماماً، وخصم المخزون ذرّي ومحمي من السباقات.
- رفع الصور يقبل صيغ الصور فقط (JPG/PNG/WebP/GIF) بحد 1.5MB، ويستلزم جلسة تاجر أو مسؤول.
- حماية من الإساءة: تحديد معدل المحاولات على الدخول والتسجيل والطلبات العامة (rate limiting) + ترويسات أمان (X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy).
- `.env` مستثنى من git تلقائياً عبر `.gitignore` — لا ترفعه أبداً إلى GitHub.
